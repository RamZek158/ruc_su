=====================================================
1) Краткое назначение проекта
=====================================================
Проект объединяет две связанные части:
1. Веб-раздел для студентов Российского университета кооперации (React + Vite + TypeScript), где размещена справочная информация по:
   - иностранным студентам,
   - воинскому учету,
   - заказу справок и документов.
2. Telegram-боты на Python (aiogram) для обработки заявок:
   - отдельный бот в корне проекта для сбора данных на справку,
   - отдельный бот в папке bot/ для записи иностранных граждан на консультацию по миграционным вопросам.

=====================================================
3) Архитектура фронтенда
=====================================================
Технологии:
- React 19
- TypeScript
- Vite 6
- Tailwind CSS через CDN в index.html
- lucide-react для иконок

Маршрутизация:
- В проекте нет react-router-dom.
- Переключение разделов реализовано вручную через состояние activeRoute в App.tsx.
- Это «внутренний роутинг» на уровне одного экрана (state-based routing).

Точка входа:
- index.tsx монтирует <App /> в #root с React.StrictMode.

Компонентный уровень:
- App.tsx:
  - хранит activeRoute,
  - на смене раздела делает window.scrollTo(0, 0),
  - рендерит один из 3 контентных компонентов.
- components/Layout.tsx:
  - общий каркас страницы: хедер, мобильное меню, боковая навигация, хлебные крошки, футер,
  - навигация строится из массива NAV_ITEMS,
  - подключен логотип из assets/logomini.png,
  - используются иконки Menu/X/ChevronRight.
- components/ForeignStudents.tsx:
  - статическая контентная страница для иностранных граждан (правила, документы, учет, контакты).
- components/MilitaryRegistration.tsx:
  - статическая контентная страница про воинский учет (кто подлежит, обязанности, документы, сроки, контакты).
- components/DocumentOrder.tsx:
  - страница заказа справок,
  - содержит ссылки на Google Form и Telegram-бота,
  - описывает сроки обработки.

Типизация и константы:
- types.ts:
  - enum PageRoute,
  - interface NavItem.
- constants.ts:
  - название университета,
  - название раздела,
  - массив пунктов меню NAV_ITEMS.

=====================================================
5) Telegram-боты (Python, aiogram)
=====================================================
В проекте присутствуют два разных сценария бота.

-------------------------------------
5.1 bot.py (в корне проекта)
-------------------------------------
Назначение:
- Сбор анкеты студента для оформления справки (в контексте воинского учета/отсрочки).

Ключевые поля формы (FSM):
- fio,
- birth_date,
- snils,
- email,
- phone,
- program,
- course,
- direction,
- study_form,
- reason.

Поведение:
- /start: старт и сброс состояния.
- Пошаговый опрос пользователя.
- В конце формируется структурированное сообщение админу (ADMIN_ID).
- Пользователь получает подтверждение об отправке.
- /cancel: отмена заполнения.
- /help: подсказка по командам.

Техдетали:
- aiogram 2.x,
- MemoryStorage (данные FSM в памяти процесса),
- отправка через bot.send_message(..., parse_mode="HTML").

-------------------------------------
5.2 bot/bot.py (в подпапке bot)
-------------------------------------
Назначение:
- Запись иностранных граждан на консультацию к специалистам по миграционным вопросам.

Ключевые поля формы (FSM):
- specialist,
- citizenship,
- topic,
- fio,
- phone,
- email,
- preferred_date,
- preferred_time,
- comment.

Поведение:
- /start: выбор специалиста (Бутова/Грибовская) и старт анкеты.
- Пошаговый сбор данных.
- Отправка итоговой заявки админу.
- Подтверждение пользователю.
- /cancel, /help.
- Дополнительная команда /specialists с описанием специалистов.

Техдетали:
- aiogram 2.x,
- MemoryStorage,
- в интерфейсе используются reply-keyboard и HTML-разметка сообщений.

=====================================================
8) Связи между частями системы
=====================================================
Связь «веб -> бот»:
- В components/DocumentOrder.tsx размещена ссылка на Telegram-бота `https://t.me/spravki_university_bot`.
- Таким образом, фронтенд выступает как информационный портал, а дальнейшее оформление переносится в Telegram.

Связь «бот -> администратор»:
- Оба Python-бота собирают данные формы через FSM и отправляют результат админу в Telegram через ADMIN_ID.

Связь «конфиг -> рантайм»:
- Vite подставляет GEMINI_API_KEY в define-переменные сборки.
- Python-боты читают BOT_TOKEN и ADMIN_ID из переменных окружения (с дефолтами в коде).

=====================================================
9) Технические наблюдения (важные для понимания проекта)
=====================================================
1. В репозитории есть два самостоятельных бота с разными бизнес-процессами.
2. В корневом README упомянут GEMINI_API_KEY, но в текущем .env.local обнаружен только VERCEL_OIDC_TOKEN.
3. index.html ссылается на /index.css, но такого файла в текущем дереве нет.
4. Внутри bot/.env.example и Python-файлов присутствуют токен/ID в качестве значений по умолчанию; для продакшена безопаснее хранить только через реальные env-переменные без хардкода.

=====================================================
10) Как запускать проект (по факту текущей структуры)
=====================================================
Frontend:
1. npm install
2. npm run dev
3. открыть http://localhost:3000

Python-боты:
- Корневой бот: python bot.py
- Бот в подпапке: python bot/bot.py
- Перед запуском нужно задать BOT_TOKEN и ADMIN_ID в окружении.
